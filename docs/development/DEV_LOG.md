| 2026-08-04 | ML | Sprint 4 Track B head start — the items that carry no Track A dependency (4.1.2, 4.2.2, 4.2.3, 4.3.6, 4.3.7, 4.3.9, 4.4.2). New `ai/retraining/` package, deliberately pure (no DB, no model loading, no HTTP) so the policy stays unit-testable and the NestJS hourly cron (4.3.3) can own *scheduling* without duplicating *policy*. (1) **Triggers** (`triggers.py`) — resolved the three thresholds the manuscript states loosely: "50 samples" = 50 admin-**validated** reports (counting raw submissions would let one user force retraining at will), "F1 drop 5%" = 5 percentage **points absolute** (at the 0.9438 baseline the absolute/relative readings differ materially, and absolute is stricter), and macro-F1 rather than accuracy since at ~62/21/17 class balance accuracy can hold while Scam recall collapses. Page-Hinkley catches the slow slide a fixed floor never trips until it is already severe. (2) **Reservoir sampling** (`sampling.py`) — Vitter's Algorithm R, one pass, fixed memory, no advance knowledge of population size, so snapshots stream out of the database instead of materialising 16k+ rows to shuffle; taking "the newest N rows" instead would over-represent whichever campaign was active that week.
